# Проверка локального стенда — 12 ноября 2026

Стенд: `/opt/team-vault`, HTTPS на порту 8443. Изменения развёрнуты через Docker Compose. Существующие ключи, данные и настройки интеграции сохранены.

## Интерфейс и границы доступа

- Серверный поиск сотрудников, руководителей, подразделений и хранилищ: по 20 результатов, продолжение списка, выбор по имени/почте, работа клавиатурой и Escape без закрытия панели.
- Проверено на отдельной временной базе с 320 синтетическими сотрудниками. Проверены узкий экран и тёмная тема. Тестовые люди не добавлялись в рабочую базу стенда.
- «Мои рабочие секреты» администратора содержит только его записи. Обычный список общих хранилищ содержит доступные ему хранилища собственного подразделения и прямые назначения.
- Глобальный просмотр вынесен в административные разделы «Секреты сотрудников» и «Все общие хранилища». Интеграции находятся в «Настройках». Для руководителей сохранён просмотр рабочих секретов своих сотрудников через «Команду».
- Поиск проверяет права на сервере и не раскрывает глобальный каталог через обычные поля выбора. В HTML полей нет полного каталога сотрудников.

## Автоматические проверки

Полный набор из 124 тестов прошёл в отдельной тестовой базе PostgreSQL (37,8 секунды). Проверяются роли, подразделения, личные пространства, поиск, назначение прав, CSRF, шифрование и привязка к контексту, TOTP и аудит, резервные коды, корзина, конфликты версий, локальный вход, OIDC/LDAP с подменёнными внешними ответами, блокировка и отзыв сессий.

Дополнительно проверены автоматическая передача резервных кодов новому руководителю, перевод сотрудника, отказ прежнему руководителю и повторная проверка прав внутри транзакции. Перенос общих записей сохраняет содержимое, историю и 2FA; обычный сотрудник и руководитель другого подразделения переносить их не могут. Копирование личной записи требует права записи в общее хранилище, создаёт новый контекст шифрования и не переносит историю, TOTP или резервные коды. Повторная отправка формы не создаёт дубликат; сбой аудита откатывает копирование. Повторная проверка внутри транзакции отклоняет отозванное право записи.

На статических страницах отдельной синтетической базы проверены иконки копирования, показ/скрытие пароля и резервного кода, сброс раскрытых значений при уходе, формы переноса/копирования, пустое хранилище и мобильная шторка. Проверены обе темы и ширины от 320 до 1440 px. Скрытие выполняется локально без дополнительного запроса; повторное раскрытие запрашивается заново. Рабочие секреты через браузерную автоматизацию не открывались.

Ручной HTTP smoke test проходит через Nginx и HTTPS с проверкой сертификата: локальный вход, административные страницы, навигация, настройки интеграций, ресурсы интерфейса и health endpoint.

`pip-audit` проверил 24 закреплённые зависимости из `requirements.lock.txt`: известных уязвимостей в ответе сервиса не найдено. Это проверка опубликованных advisories, а не независимый аудит приложения или Docker-образа.

## Эксплуатация и восстановление

- Runtime-роль PostgreSQL без SUPERUSER, CREATEDB и CREATEROLE. Пароль корневой роли БД отсутствует в окружении приложения.
- `.env` имеет закрытые права и не отслеживается Git. Образ и исходный архив не включают `.env` или базу.
- TLS 1.2/1.3 работают; тестовый сертификат не просрочен. Cookie сессии: Secure, HttpOnly, SameSite=Lax. Проверены CSP, запрет фреймов и `Cache-Control: no-store`.
- Попытка подменить `X-Forwarded-For` через Nginx отклоняется: аудит содержит адрес реального клиента. Для нового адреса Docker gateway потребуется актуализировать `TRUSTED_PROXY_IPS`.
- Время синхронизировано NTP. Во время проверки свободно около 14 ГиБ.
- Соединение Microsoft 365: OIDC discovery успешно. LDAP на стенде не настроен/выключен; реальный bind с контроллером домена не проверен.
- Истёкшие технические сессии очищены командой `cleanup_technical`; секреты, корзина и аудит не очищались.
- Зашифрованная резервная копия восстановлена в отдельный Docker-проект с собственным volume, внутренней сетью и без опубликованных портов. Контрольные суммы всех 21 таблицы совпали. Все 8 зашифрованных значений прочитаны, для 1 TOTP-конфигурации код сформирован без вывода значения. Неверный ключ отклонён. Runtime-роль клона ограничена. Проверочный проект и его volume удалены.

Последняя проверенная копия: `backup-20261112T130749Z-7a27fd.json`; 272 строки, включая технические записи. Результат: `team-vault-restore-check-58e4574f20/result.json`. Перед миграцией сохранена отдельная копия `backup-20261112T130719Z-9c1374.json`. Архивы и закрытые результаты проверок находятся на сервере в `/opt/team-vault/backups/`. Скрипты для повторения проверки: `scripts/backup.py` и `scripts/restore_check.py`; команды описаны в README.

## За пределами выполненной проверки

Нужны отдельные проверки реального входа сотрудников через Entra и AD, политик MFA/условного доступа, разрешений приложения в каталоге и блокировки внешней учётной записи. Текущая проверка Microsoft подтверждает доступность discovery, а не полную цепочку входа. Отзыв сессий внутри приложения проверен; автоматический отзыв уже выданной сессии при внешней блокировке не реализован.

Перед рабочим использованием остаются доверенный DNS/сертификат, отдельное место хранения копий и ключа, расписание копирования/очистки, процедура аварийного переключения и независимое ревью безопасности. Проверка Django `check --deploy` сообщает два ожидаемых предупреждения тестовой схемы: HSTS не включён для самоподписанного сертификата; HTTPS завершается в Nginx, а backend HTTP опубликован только на loopback. Глобальный HTTPS redirect в Django не включался, чтобы не ломать внутренний health check.
